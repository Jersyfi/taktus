# DEC-0007 — The shared kernel is a checked binding, not generated code

**Category:** DEFECT
**Raised in:** [#5](https://github.com/Jersyfi/taktus/pull/5), which adds the first slice of the control plane
**Issue:** none; a defect is corrected, not asked (ADR-0017 §2)

## 1. What this is about

The *shared kernel* is the set of concepts every part of Taktus agrees on — a step, a method, an
exactness class, a ledger entry — written as language-neutral schemas so that the core, the
workers, the web app and third-party adapters all read the same definition. The core is written
in Python and needs those concepts as Python types.

The documentation said those Python types are *generated* from the schemas by a command, `make
generate`, and never edited by hand. No generator existed, the command referred to a script that
was not there, and no Python types existed either. When the first slice of the control plane
needed them, the choice had to be made: generate them, or write them by hand and hold them to
the schemas by a test. The pull request that asked for the slice delegated that choice to the
session and asked for it to be recorded.

## 2. Why you are being asked

You are not. No row of `anchors.md` §1 applies: the schemas — the contract — do not change, and
nothing public changes. Row D2 of §2 makes the implementation of a documented mechanism the
session's call, and the pull request brief said so explicitly. The documents described a
mechanism that did not exist, which is row D6; both are corrected and recorded here.

## 3. What you must decide

Nothing. The record exists so that the reason for the choice is on file when the question comes
back — it will, the first time a schema changes and someone reaches for a generator.

## 4. What you need to know to decide

- **Generation.** A program reads each schema and writes a Python class with the same fields. The
  Python code is then a by-product; the schema is the only thing anyone edits.
- **Checked binding.** A person writes the Python class; a test reads the schema and fails when
  the class differs from it in any property, required field, enumeration or pattern, and runs
  every example of the contract through the class — valid ones must pass and write back
  identically, invalid ones must be refused.
- **Why the binding.** The schemas carry rules that no generator turns into Python: "a step on a
  method that can vary names a fallback", "a step classed exact takes its result from rule or
  statistics only", "a consumption carries at least one quantity". The core needs exactly those
  rules checked in the constructor. Generating the shape and writing the rules by hand would have
  meant two files per concept with the seam in the wrong place. The binding is one file per
  concept, and drift is a red test, which is the property generation was meant to buy.
- **What it commits the project to.** Every change to a schema is a change to one Python module
  as well, and the test says which. That is the cost, and it is visible.

## 5. Options

None for the owner. What the session did: one frozen, closed Pydantic model per schema under
`src/taktus/shared/v1/`, a module per schema file; the worker contract's shapes bound the same
way in `src/taktus/ports/worker.py`; `tests/contract/test_shared_kernel_binding.py` holds both to
the schemas and to every example; `make generate` says what is generated (nothing yet); the
documents say "bound and checked" where they said "generated".

## 6. What is blocked

Nothing.

## 7. How to answer

Nothing to answer. To choose generation after all: "Reopen DEC-0007" in an issue; the binding
test stays either way, because it is what proves the types match.

## Outcome

**Corrected:** 2026-09-16
**What was wrong:** `docs/architecture/project-structure.md` §2 and §4, `contracts/shared/v1/
README.md` and `tools/README.md` said the Python types of the shared kernel under
`src/taktus/shared/` are generated by `make generate`; no generator, no script and no types
existed.
**Why it was wrong:** the mechanism was written down before anyone had tried it; the rules the
schemas carry do not survive generation into a constructor check, which is where the core needs
them.
**What it now says:** the shared kernel and the worker contract's shapes are hand-written
bindings, checked against the schemas and their examples by `tests/contract`; `make generate` has
nothing to generate until the REST interface exists (`docs/architecture/project-structure.md` §4,
`contracts/shared/v1/README.md`, `src/taktus/shared/README.md`, `tools/README.md`).
**What changed in substance:** the contracts did not change. The Python types now exist and are
held to the contracts by a test that runs with every `make test`.
