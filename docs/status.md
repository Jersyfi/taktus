# Status

**Kept current by:** every pull request that changes the state of the project; `make
gate-status` fails when this file was not touched by one that did, when section 3 stores a list
instead of saying where it is (DEC-0026), and when the file carries a line every pull request
rewrites — a date, a running list of decisions (DEC-0027). How current it is: the date of its last
commit. What was decided when: the register's index, which `make register` prints.

This is the one file that says where the project stands and what is needed from the owner.
It states facts. Where something is not known, it says so. The roadmap (`docs/roadmap.md`)
says what each milestone must reach; this file says how far the current one has got, checked
against the code and the tests, not against what earlier descriptions claimed.

## 1. Where the project is

**Being worked: `0.4.0` to `1.0.0-beta`**, in concept mode where the owner says so: a session
builds a milestone whole and lands it in one pull request (DEC-0222). `0.1.0` and `0.3.0` have
met their completion criteria. Which issues of a milestone are open is the host's milestone, not
a list here.

Each milestone keeps where it stands in a file of its own, so that two pull requests on
different milestones never edit the same paragraph (#392):

| Milestone | Where it stands |
|---|---|
| `0.1.0` — control-plane minimum | `docs/status/0.1.0.md` |
| `0.2.0` — governance, limits, availability | `docs/status/0.2.0.md` |
| `0.3.0` — visibility | `docs/status/0.3.0.md` |
| `0.4.0` — the ML bench and the second tenant | `docs/status/0.4.0.md` |

| `0.6.0` — level 4 | `docs/status/0.6.0.md` |

How the project itself is run — how the owner is asked, the register, the gates, the vision
layer, the reviews — is `docs/status/project.md`.

A file under `docs/status/` takes a new paragraph where its subject puts it, not at the end.
A paragraph that opens with a bold lead starts an entry, and the entries follow the alphabetical
order of their leads. Two pull requests that each add an entry to the same milestone then land
apart; two that each appended one at the end conflicted (#494 after #491). One file per
paragraph would have avoided the conflict entirely, at the cost of a milestone's account read
as a folder; the order was chosen instead, and `make gate-status` holds every file to it (#498).

the next one. A session told only "continue with the next task" follows
`docs/process/next-task.md`. The list is not kept here, for the reason section 3 gives.

2026-10-20.

## 3. Needed from the owner

Every open needs request and decision request, the most urgent first. A needs request is
something only the owner can provide — a credential, an account, access, a purchase, an action,
information. A decision request is a question only the owner can answer. Each has an issue
assigned to the owner with the steps.

**The list is not kept in this file.** It is generated from the open records of the register
and carried in three places, none of which two pull requests can edit at once (DEC-0026):

- the last section of every pull request description, `## Needed from the owner`, written by
  the `owner-list` workflow from the branch's register on every push and edit (DEC-0189 rule 1,
  #314), and pasted by nobody;
- [the open issues labelled `needs-owner` or `decision-request`](https://github.com/Jersyfi/taktus/issues?q=is%3Aopen+label%3Aneeds-owner%2Cdecision-request);
- `make status` in a checkout, which prints it.
