# Status of `0.4.0` — the ML bench and the second tenant

Part of `docs/status.md`: how far `0.4.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**A backup restores the objects with the database** (#322, ADR-0087 amended). The backup
archives the object store beside the dump, and the restore of `deploy/k8s/README.md` §11 puts
both back. A test runs a process, backs it up, restores it into a fresh database and an empty
state directory, and reads every digest the run refers to. Every run records its outcome in the
database, and a failed or missing backup reaches each tenant's owner (#323, ADR-0106).

**A finding leaves an instance only as its customer chooses, signed to the project's intake**
(2026-10-22, #555, ADR-0118, DEC-0217, UC-6.12). Each release carries the list of the workers,
connectors, capabilities and operations it ships (`composition/shipped.json`), generated by
`make generate` and held to what ships by a test. A rule classifies every lack against it: a
product candidate, a lack of configuration where a shipped adapter offers it, or one of the
project's own development. A local lack never leaves; it reaches the tenant's own owner as an
alert, naming the adapter to configure. The operator's level decides how a candidate leaves:
`off` by default, `review` with `taktusctl findings review`, where "local for us" is
remembered, or `automatic`; a report by hand is always confirmed first. A candidate leaves
signed, to the intake of the project's own instance (`POST /findings/intake`), which holds a
new sender until its owner confirms it in the owner's channel, limits each sender's rate and
opens or adds to the issue with the project's one app. No second app is needed. Opening the
intake on the project's instance is NEED-0033.

**A model price list is imported into the price table** (#327, Taktus's own change). `taktusctl
prices import` turns an open model price list into a new version of the versioned price table, and
names every entry it could not map. The core names the list's shape, never its publisher
(NTC-0218).

**A proposal can be rehearsed straight from the plan dialogue, as a use case** (#329, UC-1.10,
NTC-0221). The use case is written and `specified`: a plan that ends in a new process version
offers the rehearsal, the run is marked a rehearsal and acts on nothing outside, the person sees
what it did, and commissioning waits for a rehearsal that ran through. Its implementation follows
in a pull request of its own, because a use case's requirement and the files of the tests it
names are not changed together.

**A read of the ledger costs what it returns** (#321, ADR-0105). A run start's calibration,
`GET /runs/{id}/ledger`, the blocked time and the interface sweep no longer read a tenant's
whole ledger. The calibration and the activity of runs are projections: derived from the ledger,
stored with the last sequence number they read, and rebuilt from it at any time. A chain is
verified from its last verified checkpoint, and `taktusctl ledger verify --full` walks it from
the first entry. With 500 000 entries, the calibration takes 7 to 22 ms and the ledger route 53
to 57 ms (`tests/integration/test_ledger_at_scale.py`). The four reads that still walked it
are covered by the entry "The remaining whole-ledger reads".

**A step moves to a trained model once a person accepts, and the move is measured** (#218,
ADR-0114, UC-4.3, UC-8.4, DEC-0164 provisionally Option A). A proposal of ADR-0084 accepted on
the HTTP surface or in the owner's channel registers a new version. In it the step runs on the
trained model, pinned by version and digest. Below the proposal's threshold it hands the case to
the language model it ran on, and its result says so. The replaced version stays registered and
unchanged. A step on a trained model registers only with its model's evaluation on the held-out
cases. Over the first 100 cases Taktus records the cost per case and the share that fell back,
beside the replaced version's; a move that is not cheaper is proposed for rolling back, which is
one act (`taktusctl maturation moves`, `rollback`). Against the ML bench itself, 100 cases cost
0.00000004 EUR each on the trained model against 0.000039 EUR on the language model, none fell
back, and the same case gave the same result twice
(`tests/workers/test_maturation_on_the_bench.py`). The `0.4.0` criterion is not met on an
instance yet. No step of a process Taktus runs reads numbers: each reads text, which needs
embeddings (#210). The step, its run and the two costs per case are named here once a step
reaches the floor.

**A vendor's MCP server becomes a connector, under a manifest of its effects** (2026-10-20,
#410, ADR-0117, DEC-0195 W9). The vendor connector reaches a vendor's own MCP server at the URL
its operator names and serves its tools as operations of the connector contract. A manifest,
`Connector.json#/$defs/Manifest`, declares each tool's effect, its idempotency, `native` or
`none`, and where its answer names its record. Without a manifest only the tools the vendor
marks as reading are served, each a read, and the maturity stays `experimental` whatever the
connector passed. A write nobody declared is not served, and a call to it never reaches the
vendor. The MCP project's reference time server passes the connector suite behind it, without a
manifest and with one; a stand-in with tools that write passes C-05 under its manifest, fault
for fault (`tests/conformance/test_connector_v1_vendor.py`). The catalogue does not exist yet
(#339, #348): `taktusctl conformance list` prints every configured adapter with its maturity
and says which connectors serve a vendor's server, and under which manifest.

**A wait parks its run** (#320, ADR-0103). A `wait` step longer than the runner's poll interval
no longer holds the runner's place. The run halts with cause `parked`, and its job is deferred to
the wait's next check. With four places and four runs that wait half an hour each, a fifth run
starts at once. A resumed wait counts from when it began, and its whole duration is one block of
`wait.external`.

**A wait reads a record not there yet as a state not reached** (#580, ADR-0103 amended). A `wait`
step on an outside state takes the connector's `not_found` answer of its read for a state not
reached yet and checks again at its interval until its timeout, inline or parked; the timeout's
reason names it as the last answer. Every other refusal still fails the step at once. Tests in
`tests/components/run/test_connector_steps.py`.

**A worker step starts one unit, and units share one egress gateway** (#324, ADR-0115, ADR-0005
amended, DEC-0216). A worker declares its estimator in its capabilities, `fixed` or `per_item`,
and a launched worker is estimated by it: no unit starts before admission. One probe answers the
capabilities per process. A launched worker without an estimator is refused for want of an
estimate. Units reach their hosts through one gateway of the instance, which admits per job only
the hosts its signed token names (`tests/adapters/execution/test_container.py`). With the
container adapter, a worker step creates one network and one container, against two of each unit
and two units before. In the cluster it creates one Job, one Service and one Secret, against
three Jobs, three Services and a Secret. The pod starts per worker step on the installed instance
were measured on the instance: on rc.27, three worker steps started 11 pods — 3 units, 3 egress proxies and 5 probe units, about 3.7 per step; on rc.29, five worker steps started 5 pods — one unit each, no probe and no proxy — beside the gateway's 2 pods of the chart. The chart makes the gateway's key itself (DEC-0216).

**An advisory lock never meets another tenant's** (#317, ADR-0123). The ledger's chain claim and
a projection's claim no longer hash the tenant's id into 32 bits. The chain claim is
`pg_advisory_xact_lock(2, tenant.lock_key)`, a unique number the registry assigns (migration
0062), and leadership has a namespace of its own. Tenants whose old keys were equal
(`tnt_111599`, `tnt_85816`) do not wait for each other, and a tenant writes while a leader lives
(`tests/adapters/persistence/test_ledger_store.py`). During a rolling update old and new
instances exclude nobody from each other; the chain's primary key stays the backstop.

**An expected run that does not happen raises an incident** (#427, ADR-0107, UC-4.16). A
process version declares when a run is expected, or inherits its schedule triggers. Every run
ends `ok`, `empty` or `error` in the ledger, with its duration. While it leads, the scheduler
looks once a minute. A rule over the expectation and the ledger raises an incident for a slot no
run answered within the tenant's grace period, a gap without a run, or a run over its bound.
With the scheduler stopped for one process, exactly one incident is raised for it
(`tests/integration/test_expected_runs.py`). A person closes it with `taktusctl incident`. A
watcher whose ends are mostly `empty` is reported. Delivering the incident into the business's
tracking system is UC-6.8, at `0.5.0`.

**An instance outside the project sends its findings, once its operator enables it** (2026-10-18,
#446, ADR-0112, UC-6.12). Sending is off by default. The operator enables it with one setting,
`TAKTUS_FINDINGS_CONNECTOR`, and each tenant's ledger records each change of it. A finding names
its run and step by pseudonym, under a key the instance never sends, and its sender by a random
identifier. A rule withholds any finding whose own parts carry a value of the tenant or the
shape of a personal datum. With a customer's name, an amount and an address planted in a run,
none of them reaches the issue (`tests/adapters/connectors/test_product_findings.py`). The same
lack met on two instances is one issue with two occurrences. `taktusctl findings report` takes
a bug written by hand, checks it by the same rule, shows exactly what would be sent, and sends
it only once the person confirms. ADR-0118 replaced the way it leaves (below).

**Connectors over open standards: mail, metrics and a check** (#441, ADR-0111, UC-03 §8).
Three connectors are built before the second tenant names its systems. The mail connector
reads and sends over IMAP and SMTP; a message sent is marked by its message identifier and sent
once across repeats. Its relay hands each new message to the intake, signed, and the same
message relayed twice is one event. The metrics connector reads a series by query over the
Prometheus HTTP query API. The check connector runs an HTTP check against a declared status,
body text and longest duration, and reports the outcome and the duration. Each passes the
connector suite against a local fake of its server, fault for fault
(`tests/conformance/test_connector_v1_open_standards.py`); a scenario may now name no write, for
a connector that only reads. The removal test says `untested` for each: no process uses one
yet. A receiver of OpenTelemetry data is not built (ADR-0111 §7); signed webhooks under the open
specification are #532.

**Corrections are counted, and a level falls by rule** (2026-10-18, #429, ADR-0110, UC-7.5).
A person answers a step proposed at level 1 or 2 as released, corrected or rejected, and each
answer is a ledger entry that names no person. The correction rate per process and action class,
over 7 and 28 days, is a rule over those entries (`taktusctl corrections list`). A rate above the
tenant's limit, or a breach of an anchor, lowers the process or the action one level at its next
step boundary, raises an incident and tells the owner. A level-3 process that breaches an anchor
is at level 2 before its next step (`tests/governance/test_corrections.py`). Taktus proposes a
raise when the tenant's conditions hold, and never applies one. A level that fell rises again
only by a version a person approves. The shipped limits are NTC-0215; the table
`correction_limits` is migration 0059.

**Each model purpose is served by an ordered chain, switched at the step boundary** (#328,
ADR-0116, UC-8.2 in part, NTC-0217). `TAKTUS_MODELS` names several models in order, and the
chain of a purpose is every model that serves it. Each model declares where it processes and
the exactness classes it may produce for. A tenant's residency rule (`taktusctl residency`)
permits `own`, `eu` or `anywhere`, narrowed per data class. A step takes the first model the rule
admits, that may produce its class, and that is not cooling down. A model that answers `429` or
fails cools down, and the step moves to the next one at its boundary. The wait is booked to
`limit.provider`, and the provenance names the model that answered and the route it took. A
gateway stands behind a model only as a pass-through (`deploy/docker/README.md`). Not built: a
model eligible only after its evaluation (UC-8.4), and a rule narrowed per process (UC-11.1).

**Every commit on `main` replays the self-development bundles** (#393, ADR-0108, in part). The
lane `rehearse` runs `make rehearse` on every push to `main`, and on every pull request that
touches a bundle, a recording or the core: P-01, P-02, P-03 and S-07 run as
rehearsals against a database, with every step that leaves the engine answered by the recorded
result of the same step, and every step must reach the state it reached when recorded. Deliberate
breaks — a bundle that sends another body, a recorded answer that leads elsewhere, a missing
answer — turn it red, naming the step. `tools/record_rehearsal.py` writes a recording from a run
in an instance's database, and replaces every identifier of a person by `a person`. P-02 is
replayed from a run on the instance since 2026-10-18. P-01, P-03 and S-07 are replayed from
local recordings, taken against the repository's fakes, until each has run on the instance in its
current version: P-01 and S-07 never have, and P-03 version 20 has not finished a run. #393 is
complete when they are.

**Every link to a report opens its page in the web app** (#561, ADR-0120, DEC-0218). A message
of every kind — a decision request, a need, a date, a failure or an alert, the daily signals —
links `{view_base}/app/#/reports/<id>`. The page asks for the key when the tab holds none, then
shows the report as the channel did. The reader answers there by the channel's rules, and nothing
is filed before the same reader confirms the reading; nothing is said in the channel. The start
page lists the open reports newest first, under a line that counts them, and each need on the
needs page leads to its report's page, where it is answered. A browser that opens an
old `/owner/reports/<id>` link without a key is sent to the page; a client asking for JSON is
answered as before (`tests/components/reporting/test_report_page.py`,
`tests/adapters/rest/test_owner_reports.py`, `web/src/lib/reports.test.ts`). A sign-in that
outlasts the tab, and the pages of the other records, are their own issues.

**Runners serve tenants in turn** (#319). A runner fills its places one job per tenant in
turn, starting each round one tenant further on. Behind another tenant's 1 000 queued runs, a
tenant's run starts within two poll intervals, in either order. A run that ends wakes the runner:
four places drain short runs at more than four a second, with a poll of a second.

**Signals are measured against corridors, and a daily report lists only what deviates** (#428,
ADR-0109, UC-6.13). A signal is the result of a `rule` or `statistics` step, exact or sourced,
with a provenance record. Its corridor is a yellow and a red threshold over the step's own
earlier results, or fixed bounds. A person changes it as a new version with `taktusctl signal`;
a run or a worker that tries is refused, and the refusal is recorded. A red value raises an
incident and reaches the owner's channel at once. From 06:00 UTC the daily report lists every
signal outside its corridor and every one not measured, each line with its run, its step and its
case. A confirmed reply starts an offered process as a command for the person who confirmed it.
This opens stage 0 of the second tenant (UC-03 B-9.01). The signals of the business's own
systems still need their connectors (NEED-0028).

**Signing in to the web app lasts beyond a browser tab** (2026-10-22, #564, ADR-0119,
DEC-0218). The web app sends the account key once to `POST /session` and forgets it. The
instance answers with a session cookie that no script of the page can read: `HttpOnly`,
`Secure`, `SameSite=Strict`, valid for `TAKTUS_SESSION_HOURS` (12 by default). A link opened in a
new tab shows its page at once. The cookie is accepted wherever the key is, the live stream
included, and the key keeps working for every other client. A session ends at its time, on
*Sign out*, and when the identity's key is replaced. A write with the cookie from another site
is refused. Only a digest of the token is kept, in `browser_session` (migration 0063). The key
is never stored by the page, never in an address and never logged
(`tests/adapters/rest/test_session.py`, `web/src/lib/session.test.ts`).

**Skills are `SKILL.md`, coding workers read `AGENTS.md`, and a bundle is checked without an
instance** (2026-10-18, #407, ADR-0113, DEC-0195 W6). ADR-0113 chooses the open `SKILL.md`
format for skills. It says where a skill lives in a bundle, and that a step names it by name,
never by product. Nothing loads a skill until the lifecycle of `0.6.0`. Both coding workers hand
their agent the target repository's `AGENTS.md`, before the task and once per session
(`tests/conformance/test_coding_workers_brief.py`). This repository's `AGENTS.md` points to
`CLAUDE.md` and carries no rule (NTC-0216). `taktusctl bundle check` holds a bundle to
registration's rules with no instance, no database and no login. `examples/README.md` documents
a CI job for a repository that holds bundles (`tests/integration/test_bundle_check_command.py`).

**Tenants created by a command** (2026-10-18, #318). The table `tenant` is the instance's
registry, and the identity component owns it (ADR-0104). `taktusctl tenant create` and `POST
/administration/tenants` create a tenant with a display name; Taktus generates the identifier.
Every role reads the registry at every round, so a tenant created while the daemon runs is
served without a restart (`tests/integration/test_tenant_registry.py`). Each creation is the
first entry of the new tenant's chain. `TAKTUS_TENANTS` only narrows the registry now, and is
removed in the following minor release (#517). The second tenant will be created this way.

**The concurrent-claim test checks exclusivity within a lease** (#552). The queue suite's lease
is an hour, so that a claim cannot expire by the clock while the machine is loaded; a test that
needs an expired lease makes one. `claimed_at` stays the claiming transaction's start
(`now()`): the claim is one short statement in a transaction of its own, so the difference is
milliseconds, and a migration and an amendment for it would buy nothing.

**The correction figures and the alert sweep cost what they return** (#550, ADR-0105 §10). The
figures of UC-7.5, the raises Taktus proposed and the verdict after a decision read the projection
`governance.corrections.v1`: the decisions of the last 35 days per unit and the figures of each
proposal, which equal the rule over every entry
(`tests/components/governance/test_correction_state.py`). A read it cannot answer is made from the
entries of the four kinds. The sweep every minute reads the capacity crossings and the lost claims
by their kinds. Neither reads the whole ledger (`tests/fakes/guarded.py`,
`tests/governance/test_correction_reads.py`). With 500 000 entries, 2 000 of them decisions, the
figures take 3 ms, the raises 4 ms and the sweep 14 ms
(`tests/integration/test_ledger_at_scale.py`).

**The remaining whole-ledger reads cost what they return** (#522, ADR-0105 §9). The Takt rate
is a projection, `accounting.takt.v1`, per day and run: the whole days of its window come from it,
the two partial days from the ledger by kind and time (migration 0060). The measures read the
corrections. The quality history of a raise and of a
registration is a projection, `process.quality.v1`, that equals `autonomy.history` over every
entry (`tests/components/process/test_quality.py`). None of the four reads the whole ledger
(`tests/fakes/guarded.py`). With 500 000 entries, the history takes 9 ms, the Takt rate over 30
days 30 ms and the measures 2 ms (`tests/integration/test_ledger_at_scale.py`).

**The second tenant** (2026-10-14). The business's catalogue arrived before the date, so plan B
does not start (NEED-0027 provided, DEC-0199). The second tenant is a small software business:
96 use cases in eleven areas, introduced in six stages from a daily report to a business that
runs without staff in normal operation. UC-03 (`docs/usecases/AF-03-software-operations.md`)
maps every use case to a process and a target level; nine function-level use cases state what no
use case required yet (NTC-0210). Stage 0 is `0.4.0` (#400), stage 5 is `1.0.0` (#440), and
`1.0.0` is not complete without it. Nothing of it is built. What the catalogue did not say —
the business's systems, volumes, roles and where its data may go — is NEED-0028 (#426).
The business hosts Taktus itself, opens its stages itself, and its findings improve the product;
every connector it needs is built here (DEC-0201). Running Taktus needs the owner's written
permission first, because the licence is not decided (NEED-0029, #444).

**The tests of wall-clock time run alone** (#528, ADR-0096 §7). The three bounds of
`tests/integration/test_ledger_at_scale.py` stay at 200 ms and 50 ms. The tests marked `timing`
are the lane `timing`: a job of its own in CI, on every commit of `main` too, and the last lane
of `make verify`, which holds the machine for it (`tools/machine_lock.py`), so that two
sessions' verify runs no longer measure each other.

**The web app is where everything is found** (DEC-0218, 2026-10-22). The owner asked that every
link a channel carries opens a page of the web app under the reader's sign-in, and that the web
app shows everything Taktus holds for its reader's role. On that day an alert's link answered
`401`, and nothing built since #308 had reached the web app. The work is issues in `0.4.0`.

**The web app shows what governs the work** (2026-10-22, #563, ADR-0122, DEC-0218). Four pages
are new: the needs, each process's level with its correction rates, the findings with their
review, and the tenants under the administration key. The start page has one line per kind,
saying how many are open or waiting. `GET /autonomy` answers the levels and the rates per
process and action class over 7 and 28 days; no figure names a person. `GET /findings` answers
the findings with their classification. An answer in review is read back first by `POST
/findings/{lack}/review`, and only its confirmation of the same text acts.

**The web app shows what keeps the operation running** (#562, ADR-0121, DEC-0218). The
incidents, the alerts, the backup and the signals each have a page of the web app, reached from
the start page. The start page opens with a sentence of what needs a look, then one line per
kind with how many are open or red. Each record links its run, its step or its process version,
and none names a person. The surface reads each from the component that owns it: `GET
/incidents`, `/alerts`, `/backup`, `/signals`, `/signals/daily-report`, and `GET /operation`
for the start page. An incident and a signal are shown to every reader who may see their
process; an alert, the backup and the daily report to the owner and the people the owner named
(`tests/adapters/rest/test_operation.py`, `web/src/lib/operation.test.ts`).

**W-06 and W-11 reach their verdict at any load** (#551). The suite stops the work at the start
of the step that produced the first artifact. Under a parallel `make verify` the request could
reach the worker after the work had finished, and both checks ended inconclusive on the speed of
the machine. A stop that comes too late is now made again, up to four runs in all; a worker that
repeats an artifact on resume still fails W-11
(`tests/conformance/test_worker_v1_late_stop.py`,
`tests/conformance/test_worker_v1_faults.py`).

**What needs a person's action reaches the owner's channel** (2026-10-18, #323, ADR-0106).
Three signals become a report of kind `failure` in each tenant's owner-facing channel, as a
broken interface does (ADR-0047): a capacity finding that turns to *act*, a runner that lost its
claim on a run (`run.claim_lost`, new), and a failed or missing backup. The backup records every
run's outcome in the table `backup_outcome` (migration 0055); the chart expects one every 26
hours. Each is said once and sends nothing new until it clears or the owner answers it done. A
tenant without a channel hears nothing, the startup log names it, and `taktusctl alerts` shows
what it would have heard (`tests/composition/test_alerts.py`).
