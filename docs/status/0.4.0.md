# Status of `0.4.0` — the ML bench and the second tenant

Part of `docs/status.md`: how far `0.4.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**A backup restores the objects with the database** (#322, ADR-0087 amended). The backup
archives the object store beside the dump, and the restore of `deploy/k8s/README.md` §11 puts
both back. A test runs a process, backs it up, restores it into a fresh database and an empty
state directory, and reads every digest the run refers to. Every run records its outcome in the
database, and a failed or missing backup reaches each tenant's owner (#323, ADR-0106).

**A read of the ledger costs what it returns** (#321, ADR-0105). A run start's calibration,
`GET /runs/{id}/ledger`, the blocked time and the interface sweep no longer read a tenant's
whole ledger. The calibration and the activity of runs are projections: derived from the ledger,
stored with the last sequence number they read, and rebuilt from it at any time. A chain is
verified from its last verified checkpoint, and `taktusctl ledger verify --full` walks it from
the first entry. With 500 000 entries, the calibration takes 7 to 22 ms and the ledger route 53
to 57 ms (`tests/integration/test_ledger_at_scale.py`). The Takt rate, the measures, the quality
history of a raise and the registration of a version still read the whole ledger (#522).

**A wait parks its run** (#320, ADR-0103). A `wait` step longer than the runner's poll interval
no longer holds the runner's place. The run halts with cause `parked`, and its job is deferred to
the wait's next check. With four places and four runs that wait half an hour each, a fifth run
starts at once. A resumed wait counts from when it began, and its whole duration is one block of
`wait.external`.

**An expected run that does not happen raises an incident** (#427, ADR-0107, UC-4.16). A
process version declares when a run is expected, or inherits its schedule triggers. Every run
ends `ok`, `empty` or `error` in the ledger, with its duration. While it leads, the scheduler
looks once a minute. A rule over the expectation and the ledger raises an incident for a slot no
run answered within the tenant's grace period, a gap without a run, or a run over its bound.
With the scheduler stopped for one process, exactly one incident is raised for it
(`tests/integration/test_expected_runs.py`). A person closes it with `taktusctl incident`. A
watcher whose ends are mostly `empty` is reported. Delivering the incident into the business's
tracking system is UC-6.8, at `0.5.0`.

**Every commit on `main` replays the self-development bundles** (#393, ADR-0108, in part). The
lane `rehearse` runs `make rehearse` on every push to `main`, and on every pull request that
touches a bundle, a recording or the core: P-01, P-02, P-03 and S-07 run as
rehearsals against a database, with every step that leaves the engine answered by the recorded
result of the same step, and every step must reach the state it reached when recorded. Deliberate
breaks — a bundle that sends another body, a recorded answer that leads elsewhere, a missing
answer — turn it red, naming the step. `tools/record_rehearsal.py` writes a recording from a run
in an instance's database. The recordings under `tests/rehearsal/recordings/` are local ones,
taken against the repository's fakes; #393 is complete when recordings from the instance replace
them.

**Runners serve tenants in turn** (#319). A runner fills its places one job per tenant in
turn, starting each round one tenant further on. Behind another tenant's 1 000 queued runs, a
tenant's run starts within two poll intervals, in either order. A run that ends wakes the runner:
four places drain short runs at more than four a second, with a poll of a second.

**Signals are measured against corridors, and a daily report lists only what deviates** (#428,
ADR-0109, UC-6.13). A signal is the result of a `rule` or `statistics` step, exact or sourced,
with a provenance record. Its corridor is a yellow and a red threshold over the step's own
earlier results, or fixed bounds. A person changes it as a new version with `taktusctl signal`;
a run or a worker that tries is refused, and the refusal is recorded. A red value raises an
incident and reaches the owner's channel at once. From 06:00 UTC the daily report lists every
signal outside its corridor and every one not measured, each line with its run, its step and its
case. A confirmed reply starts an offered process as a command for the person who confirmed it.
This opens stage 0 of the second tenant (UC-03 B-9.01). The signals of the business's own
systems still need their connectors (NEED-0028).

**Tenants created by a command** (2026-10-18, #318). The table `tenant` is the instance's
registry, and the identity component owns it (ADR-0104). `taktusctl tenant create` and `POST
/administration/tenants` create a tenant with a display name; Taktus generates the identifier.
Every role reads the registry at every round, so a tenant created while the daemon runs is
served without a restart (`tests/integration/test_tenant_registry.py`). Each creation is the
first entry of the new tenant's chain. `TAKTUS_TENANTS` only narrows the registry now, and is
removed in the following minor release (#517). The second tenant will be created this way.

**The second tenant** (2026-10-14). The business's catalogue arrived before the date, so plan B
does not start (NEED-0027 provided, DEC-0199). The second tenant is a small software business:
96 use cases in eleven areas, introduced in six stages from a daily report to a business that
runs without staff in normal operation. UC-03 (`docs/usecases/AF-03-software-operations.md`)
maps every use case to a process and a target level; nine function-level use cases state what no
use case required yet (NTC-0210). Stage 0 is `0.4.0` (#400), stage 5 is `1.0.0` (#440), and
`1.0.0` is not complete without it. Nothing of it is built. What the catalogue did not say —
the business's systems, volumes, roles and where its data may go — is NEED-0028 (#426).
The business hosts Taktus itself, opens its stages itself, and its findings improve the product;
every connector it needs is built here (DEC-0201). Running Taktus needs the owner's written
permission first, because the licence is not decided (NEED-0029, #444).

**What needs a person's action reaches the owner's channel** (2026-10-18, #323, ADR-0106).
Three signals become a report of kind `failure` in each tenant's owner-facing channel, as a
broken interface does (ADR-0047): a capacity finding that turns to *act*, a runner that lost its
claim on a run (`run.claim_lost`, new), and a failed or missing backup. The backup records every
run's outcome in the table `backup_outcome` (migration 0055); the chart expects one every 26
hours. Each is said once and sends nothing new until it clears or the owner answers it done. A
tenant without a channel hears nothing, the startup log names it, and `taktusctl alerts` shows
what it would have heard (`tests/composition/test_alerts.py`).
