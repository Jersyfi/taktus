# Status of `0.5.0` — value and dependency measurable

Part of `docs/status.md`: how far `0.5.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**A person takes over a running step** (ADR-0128, #404). Built in the engine, the runner, the
queue (migration `0064`) and the HTTP surface: a take-over is asked on the run's job by the
first asker only, the worker stops at its next boundary, its state becomes an artifact, and the
person holds the job under a claim of their own for eight hours. The hand-back is a `human`
step with provenance, written under that claim; a lapsed claim gives the step back to its
worker at the checkpoint. Still open: the web app and the chat offer it, the MCP surface waits
for #406, and the automated takeover test of UC-6.3 does not yet exercise it.

**Taktus watches its platform** (ADR-0031). The *Observe* stage is built: free CPU, memory and
storage, growth per run extrapolated to a date, `taktusctl capacity` and a report by the
scheduler, admission against free capacity, every job's memory limit enforced or the job
refused. *Propose* (`0.5.0`) and *Manage* (`0.7.0`) are specified in
`docs/architecture/platform.md`.

**UC-4.19 requires the take-over of a running step** (NTC-0223, DEC-0195 W3). A person takes a
worker step out of a running run, receives its state, and hands the result back as a `human`
step; nobody works the step twice. State `specified`; issue #404 builds it.
