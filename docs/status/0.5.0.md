# Status of `0.5.0` — value and dependency measurable

Part of `docs/status.md`: how far `0.5.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**A person takes over a running step** (ADR-0128, #404). Built in the engine, the runner, the
queue (migration `0064`) and the HTTP surface: a take-over is asked on the run's job by the
first asker only, the worker stops at its next boundary, its state becomes an artifact, and the
person holds the job under a claim of their own for eight hours. The hand-back is a `human`
step with provenance, written under that claim; a lapsed claim gives the step back to its
worker at the checkpoint. The web app's run page offers it on a running worker step, shows the
state and the lease's end, reads the result back before it is handed back, and says when a
take-over lapsed or was refused; the run level says where each served take-over stands. The
owner's conversation reads `take over <run> <step>`, `show takeover <takeover>` and `hand back
<takeover>: <result>`, and acts only on a confirmed reading. A person's own agent asks, shows and hands back over MCP
(ADR-0131). Still open: the automated takeover test of UC-6.3 does not yet exercise it.

**A person's own agent reaches Taktus over MCP** (ADR-0131, #406). Built in the identity
component, the `api` role and the composition (migration `0066`): the `api` role serves MCP at
`<prefix>/mcp`, stateless; an agent key, created by the person with `POST /identity/agent-key`,
opens it and nothing else; eleven tools read processes, runs and decision requests, start a
process, answer and confirm a decision request, and take over a step and hand it back. A tool
that acts is listed and served only where a role the person holds was granted its right
(`taktusctl identity grant`); without one the agent reads, and a write is refused naming the
right. Every call is a ledger entry `agent.<tool>` with the person as actor. Still open: rights
per role on the other surfaces (UC-7.3).

**A process caps its open work, and a step that repeats itself is stopped** (ADR-0132, UC-8.12,
#433). Built in the run, at registration and in governance (migration `0067`): a version
declares `open_work`, a cap per kind of outcome with a connector reading; before a run starts
anything it counts what is open outside and the process's runs in flight, and at the cap it
waits, booked to `wait.external` and counted again at the cap's next check. Only a person
changes a cap; a version that changes one without approval is refused and recorded. The same
outward call with the same arguments, or a model's answer, beyond the tenant's limit within a
run is stopped at the step's boundary by a rule over the ledger and raises an incident
(`taktusctl incident configure`). Defaults by NTC-0226; the twentieth `unlisted` notice raised
the override review DEC-0221. Still open: a worker's own tool calls and model calls are not
counted, because the worker contract does not say which act outward and reports no model call.

**A process declares its deadlines, and Taktus keeps them** (ADR-0133, UC-4.17, #430). Built
in the process, the run and the scheduler (migration `0068`): a version declares `deadlines`,
each with the moment it starts from, its limit, an optional lead time, calendar or working
time, the step that meets it and the action at the lead and at the limit: a reminder or an
escalation to a role, or a start of a process. A run carries its version's deadlines; the entry
that starts or meets one does so in its own transaction, and the elected scheduler takes each
action once, across restarts and with two schedulers. `taktusctl deadline list` lists the open
ones by when they fall due, with the link to the case; `taktusctl deadline working-time` sets
the tenant's working time, whose default NTC-0227 sets. Still open: a reminder and an
escalation are listed for the role on the control plane's surface, not delivered into a chat.

**A step sees only the data of its case** (ADR-0130, UC-7.7, #432). Built in the run, at
registration, in the connector contract and in governance (migration `0065`): a step's `scope`
names its subject from the run's inputs and rides on every connector call; a scoped capability
refuses another subject's data with `out_of_scope`, recorded as `frame.refused`; an `analytic`
step reaches its one source through reads only, a source the tenant declares free of personal
fields with `taktusctl sources`; a step that reads personal data outside a case waits for a
person at every level; the provenance record names the scope. Defaults by NTC-0224. Still open:
the conformance suite does not yet check a scoped capability, and no connector here serves one.

**Taktus watches its platform** (ADR-0031). The *Observe* stage is built: free CPU, memory and
storage, growth per run extrapolated to a date, `taktusctl capacity` and a report by the
scheduler, admission against free capacity, every job's memory limit enforced or the job
refused. *Propose* (`0.5.0`) and *Manage* (`0.7.0`) are specified in
`docs/architecture/platform.md`.

**UC-1.11 requires that a person's own agent reaches Taktus** (NTC-0225, DEC-0195 W5). A
person's agent reaches Taktus over the Model Context Protocol: it starts a process, reads its
runs, answers a decision request and takes over a step, as the person and only with the rights
of their role, and reads only where no right was granted. State `specified`; #406 builds it.

**UC-4.19 requires the take-over of a running step** (NTC-0223, DEC-0195 W3). A person takes a
worker step out of a running run, receives its state, and hands the result back as a `human`
step; nobody works the step twice. State `building`: the engine, the HTTP surface, the web app,
the chat and the MCP surface name their tests; the automated takeover test remains.
