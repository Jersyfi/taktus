# Status of `0.5.0` — value and dependency measurable

Part of `docs/status.md`: how far `0.5.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**A change is held to its evaluation cases, and drift is measured on them** (ADR-0134, UC-4.18,
#431, #408). Built in the process component, in governance and in the composition (migration
`0069`): a version declares `evaluation`, its cases with a target per step, its scorers — a
rule, or a language model as judge that says why no rule can and falls back to a rule or a
person — and a schedule. Rehearsing a proposal that changes a step runs every case as a
rehearsal on the active version and on the proposal; a score below the active version's by more
than the tenant's tolerance blocks commissioning, unless a person overrides it with a reason.
On the schedule the same cases run with no change; a drift is recorded, and raises an incident
where the process sends outward. Every case names the model the provider reported. A corrected
draft is proposed as a case, reduced to the inputs the steps read, withheld where it would keep
a subject the tenant does not allow, and enters the set once a person confirms it. Defaults by
NTC-0228. Still open in #408: the web app and the owner's conversation do not show the
comparison, and maturation does not read the scores.

**A cost watcher reads the cloud bill, and connectors read costs, payments and errors**
(ADR-0150, ADR-0151, UC-03 B-1.01, #447). Built in the adapters, the run and the blueprint
`software-operations`: four connectors, each named by capability and passing the connector
suite against a fake of its product's API, fault for fault — `billing.costs` (daily cost by
service, every request signed with a key pair), `models.costs` (a model provider's daily cost,
from either of two providers' APIs),
`errors.issues` and `payments.subscriptions`; every amount stays decimal text, and nothing that
names a person is passed on. A `statistics` step runs for the first time: `deviation` computes
the day's total, the median of the weeks before it and the service behind a jump, in decimal.
The cost watcher, `B-1.01-daily-cost.yaml`, reads the bill and measures with it, and
`B-2.01-model-cost.yaml` does the same for a model provider's spend; a tenant's corridor on
the `ratio` raises the incident, both proven end to end against fakes
(`tests/composition/test_cost_watcher.py`). Still open for the first beta condition: the run on
the project's own instance against the real service (NEED-0036, the model provider's cost
report, recommended; or NEED-0035), and a way for the
chart to run a further connector. Still open in #447: payment reconciliation (B-6.01), which
needs the product's entitlements, and the credit left at a model provider, which its API does
not give.

**A first process comes from the gallery, and the time to it is measured** (ADR-0136,
UC-10.4, #405). Built in the process component, the composition, the HTTP surface, the command
line, the web app and the deployment: `blueprints/gallery/` holds a family, a club and a small
business, each one bundle of two rule steps, read from `TAKTUS_GALLERY_DIRECTORY` on every
request and offered only at level 1 or 2; choosing one writes the person's choices into its
schedule trigger and makes a proposal against no version, which the plan dialogue rehearses and
commissions. `make start` installs on one machine, creates the first tenant and its
administrator with `taktusctl first start`, prints the key once, and keeps a clock until the
first rehearsal has finished; `make verify-first-process` goes the path without a person and
fails above ten minutes (`docs/runs/first-process-in-ten-minutes.md`). Still open in #405: the
trial with a person new to Taktus (NEED-0034); on a cluster, no command creates the first
tenant and no clock runs.

**A human step and a fallback to a person name a role** (ADR-0146, UC-4.20, #331). Built in
the shared kernel, at registration, in the identity component and in the process level: a
`human` step and a fallback to a person carry `role` and optional `expertise`, never elsewhere;
once an identity of the tenant holds a role, registration refuses a person's step without a
role, or with one nobody holds. The web app's process page shows the role. Still open: a run
does not yet address the wait at a human step to its role.

**A person takes over a running step** (ADR-0128, #404). Built in the engine, the runner, the
queue (migration `0064`) and the HTTP surface: a take-over is asked on the run's job by the
first asker only, the worker stops at its next boundary, its state becomes an artifact, and the
person holds the job under a claim of their own for eight hours. The hand-back is a `human`
step with provenance, written under that claim; a lapsed claim gives the step back to its
worker at the checkpoint. The web app's run page offers it on a running worker step, shows the
state and the lease's end, reads the result back before it is handed back, and says when a
take-over lapsed or was refused; the run level says where each served take-over stands. The
owner's conversation reads `take over <run> <step>`, `show takeover <takeover>` and `hand back
<takeover>: <result>`, and acts only on a confirmed reading. A person's own agent asks, shows and hands back over MCP
(ADR-0131). Still open: the automated takeover test of UC-6.3 does not yet exercise it.

**A person's own agent reaches Taktus over MCP** (ADR-0131, #406). Built in the identity
component, the `api` role and the composition (migration `0066`): the `api` role serves MCP at
`<prefix>/mcp`, stateless; an agent key, created by the person with `POST /identity/agent-key`,
opens it and nothing else; eleven tools read processes, runs and decision requests, start a
process, answer and confirm a decision request, and take over a step and hand it back. A tool
that acts is listed and served only where a role the person holds was granted its right
(`taktusctl identity grant`); without one the agent reads, and a write is refused naming the
right. Every call is a ledger entry `agent.<tool>` with the person as actor. Still open: rights
per role on the other surfaces (UC-7.3).

**A process caps its open work, and a step that repeats itself is stopped** (ADR-0132, UC-8.12,
#433). Built in the run, at registration and in governance (migration `0067`): a version
declares `open_work`, a cap per kind of outcome with a connector reading; before a run starts
anything it counts what is open outside and the process's runs in flight, and at the cap it
waits, booked to `wait.external` and counted again at the cap's next check. Only a person
changes a cap; a version that changes one without approval is refused and recorded. The same
outward call with the same arguments, or a model's answer, beyond the tenant's limit within a
run is stopped at the step's boundary by a rule over the ledger and raises an incident
(`taktusctl incident configure`). Defaults by NTC-0226; the twentieth `unlisted` notice raised
the override review DEC-0221. A worker's own calls count too (ADR-0144): a tool call it marks
outward and its model's answers without a tool result between, as the worker contract reports
them (ADR-0139); a count beyond the limit stops the worker at its next boundary with its
checkpoint, and the run halts with cause `repeated`. UC-8.12 is built.

**A process declares its deadlines, and Taktus keeps them** (ADR-0133, UC-4.17, #430). Built
in the process, the run and the scheduler (migration `0068`): a version declares `deadlines`,
each with the moment it starts from, its limit, an optional lead time, calendar or working
time, the step that meets it and the action at the lead and at the limit: a reminder or an
escalation to a role, or a start of a process. A run carries its version's deadlines; the entry
that starts or meets one does so in its own transaction, and the elected scheduler takes each
action once, across restarts and with two schedulers. `taktusctl deadline list` lists the open
ones by when they fall due, with the link to the case; `taktusctl deadline working-time` sets
the tenant's working time, whose default NTC-0227 sets. Still open: a reminder and an
escalation are listed for the role on the control plane's surface, not delivered into a chat.

**A process shows how it really runs** (ADR-0147, UC-9.7, #334). Built in the run, the
reporting component, the composition, the HTTP surface and the web app: a step admitted again
after it failed is recorded as `step.retried`; the projection `reporting.variants.v1` keeps each
run's fallbacks to a person, retries, anchor halts and take-overs and how it ended, and
`GET /processes/{id}/variants` ranks the variants with their share against the designed path,
shows the waiting by step and cause, a role's waiting only where two hold it, and proposes a
method change or a rule, which a person decides in a change in dialogue. Page `#/variants/<id>`,
linked from the process. Still open: the thresholds are defaults a tenant does not set.

**A step sees only the data of its case** (ADR-0130, UC-7.7, #432). Built in the run, at
registration, in the connector contract and in governance (migration `0065`): a step's `scope`
names its subject from the run's inputs and rides on every connector call; a scoped capability
refuses another subject's data with `out_of_scope`, recorded as `frame.refused`; an `analytic`
step reaches its one source through reads only, a source the tenant declares free of personal
fields with `taktusctl sources`; a step that reads personal data outside a case waits for a
person at every level; the provenance record names the scope. Defaults by NTC-0224. Still open:
the conformance suite does not yet check a scoped capability, and no connector here serves one.

**A stop can be scoped to an adapter, and is confirmed once it holds** (ADR-0138, #436, #621). Built
in the run, the runner, the scheduler and `taktusctl stop`. A stop of a configured worker hands
it no step and stops every step inside it at the worker's boundary, at the runner's next
renewal. A stop of a configured connector or model holds back every call to it, before the
call: the step stops at its boundary, a wait between two checks, a step whose model chain moves
to it there (#621). Runs on other adapters go on. Once no run is inside a step on it, the stop
is confirmed once, addressed to the requester, naming the runs it halted; a person lifts it.
Migration 0072. The register requests it over the HTTP surface and the web app (#332); not yet
built: a stop from chat or MCP.

**A tenant is introduced in stages, each opened by a person on the rule's figures** (ADR-0137,
UC-9.6, #434). Built in governance, at registration and in the composition (migration `0073`):
a tenant declares its stages with `taktusctl stage declare`, each with the processes it adds,
the level each may reach and a holding condition over the ledger — weeks, runs, missed runs,
incidents, correction rate, proposals waiting. A process of a stage not open is refused above
level 2, naming the stage and what it lacks. Only a person opens a stage, once the one before
it holds by its rule and every process it adds has takeover instructions; Taktus proposes the
opening to the responsible role. A stage that stops holding is reported, and its processes fall
by rule to the level its absence allows. `taktusctl stage show` computes every figure from the
ledger. A plan names no person and is never looser than its blueprint;
`blueprints/software-operations/stages.yaml` proposes UC-03's six stages (NTC-0232). Still
open: no process version carries takeover instructions until UC-6.3 is built, so no stage opens
on an instance before then; the web app does not show the stages.

**A unit the cluster is still creating is waited for** (#634, ADR-0145). On the install of
2026-10-28 two runs escalated because their worker's unit was still pulling its image when its
health bound of 120 seconds passed. The cluster adapter now reads `ContainerCreating`,
`PodInitializing` and a placed `Pending` pod as a platform at capacity: the step waits, bounded
by its capacity ceiling, and past it fails with the cluster's reason. A unit that runs and
answers nothing, or cannot pull its image, fails as before
(`tests/adapters/execution/test_kubernetes.py`, `tests/components/run/test_capacity_wait.py`).

**An upgrade that changes the schema keeps the instance ready** (ADR-0093 amended, #330).
Built in the persistence adapter, the composition, migration `0083` and the deployment.
Readiness accepts a range: a build is ready from `OLDEST_SCHEMA` (its head unless set) to its
head, and against a newer revision while the schema's function `taktus_oldest_code()` names a
revision of the build's own history. A daemon that migrates on start leaves a newer schema as it
is. Every migration from `0083` on is compared with the schema before it, and one that narrows
without moving the function fails (`tests/adapters/persistence/test_migrations_expand.py`).
`deploy/docker/upgrade.sh` runs the new migrations while the previous release serves, and
holds its readiness once that release reads the range. The rollback runbook is section 12 of
`deploy/k8s/README.md`. Still open: the first release step it covers is from the first
release that carries it; the releases before it stay unready against a newer schema.

**Every tenant of the registry is served, and nothing narrows it** (ADR-0104 amended, #517).
`TAKTUS_TENANTS` is removed: no setting reads it, `TenantRegistry` has no narrowing, and a
daemon that still sets it to a value refuses to start with a message that names `taktusctl
tenant create`. No minor release carried the deprecated variable, so ADR-0104 §7 is amended
rather than waited for. Each integration test runs against a database of its own, copied from
a template migrated once per session (`tests/integration/conftest.py`).

**One register shows everything that acts for a tenant** (ADR-0147, UC-7.8, #332). Built in
the reporting component, the composition, the HTTP surface and the web app: `GET /register`
lists every configured worker, connector and model with the processes and steps it acts in,
their highest level and strongest exactness class, its maturity and last removal verdict, where
it processes against the residency rule, what its steps used over 28 days from the projection
`reporting.used.v1`, and a held stop; rows that need attention come first with their reasons.
`POST /register/{adapter}/stop` requests the adapter stop of ADR-0138; `GET /register/inventory`
writes the AI Act inventory, marked not legally reviewed. Page `#/register`, linked from every
page's bar. Still open: agents and skills appear through their adapters until their hubs exist.

**Taktus watches its platform** (ADR-0031). The *Observe* stage is built: free CPU, memory and
storage, growth per run extrapolated to a date, `taktusctl capacity` and a report by the
scheduler, admission against free capacity, every job's memory limit enforced or the job
refused. *Propose* (`0.5.0`) and *Manage* (`0.7.0`) are specified in
`docs/architecture/platform.md`.

**The trace inside a step is seen as it happens, and shared by role** (ADR-0135, #409).
Built in the run, the reporting component, the HTTP surface and the web app (migration
`0070`): the run keeps every event a worker reports as a line of its step's trace, every secret
value masked, outside the ledger. The run's page shows the trace of each worker step and asks
again every two seconds while the step is in flight; an event reaches a reader within the five
seconds, by a named test. A trace is shown to the run's readers who hold the role `owner` or a
role it is shared with; a share names a role, never a person, and is a ledger entry. Each tenant
sets its retention with `taktusctl trace retention` (30 days by default, NTC-0230), and the
scheduler erases what it ended. Still open in #409: UC-6.14 is `specified` until #613 merges,
and its tests are named after.

**UC-1.11 requires that a person's own agent reaches Taktus** (NTC-0225, DEC-0195 W5). A
person's agent reaches Taktus over the Model Context Protocol: it starts a process, reads its
runs, answers a decision request and takes over a step, as the person and only with the rights
of their role, and reads only where no right was granted. State `specified`; #406 builds it.

**UC-10.4 requires a first rehearsed process in ten minutes** (NTC-0231, DEC-0195 W4). One
command installs Taktus; a gallery of blueprints in open files, for a family, a club and a small
business, leads into the plan dialogue; the first process is rehearsed before it goes live; a
script records the time from the install command to the end of the rehearsal, with a person new
to Taktus, and the time is reported. State `specified`; #405 builds it.

**UC-4.19 requires the take-over of a running step** (NTC-0223, DEC-0195 W3). A person takes a
worker step out of a running run, receives its state, and hands the result back as a `human`
step; nobody works the step twice. State `building`: the engine, the HTTP surface, the web app,
the chat and the MCP surface name their tests; the automated takeover test remains.

**UC-4.20 requires a role at every point where a person acts** (NTC-0237, DEC-0190 F2). A human
step and a fallback to a person name the role of the structure that acts there, never a person,
and registration requires it once the tenant has a structure. State `building`.

**UC-6.14 requires the trace inside a step** (NTC-0229, DEC-0195 W8). What a worker reports
while it works a step is shown at the step in the run level within 5 seconds, shared with a role
by a link only an identity of that role opens, kept outside the ledger for the tenant's retention
and then deleted, with every secret masked. State `specified`; #409 builds it.

**UC-6.15 requires a stage view for people inside a run** (NTC-0235, DEC-0190 F9). A
participant who is not technical sees a run as its stages: done, current, or ahead, and for a
waiting stage the role it waits for. The view is drawn from the records of the run level and
stores nothing. State `specified`; #335 builds it.

**UC-6.16 requires what breaks if an adapter goes, and where a wrong result went** (NTC-0239,
DEC-0190 F5). Derived from bundles, configuration and provenance, never kept by hand. State
`building`.

**UC-7.2 requires a stop scoped to an adapter, confirmed once it holds** (NTC-0233, DEC-0199).
A stop of one adapter halts every run it serves at its boundary, and runs on other adapters go
on. Whoever requested a stop is told once every affected run has reached its boundary, with the
runs it stopped. State `building`: #436 built it for workers, #621 for connectors and models;
the tests are named in the use case.

**UC-7.8 requires one register of everything that acts for a tenant** (NTC-0238, DEC-0190 F4),
with a stop and an AI Act inventory marked not legally reviewed. State `building`.

**UC-9.7 requires that a process shows how it really runs** (NTC-0240, DEC-0190 F6): variants,
waiting by cause and proposals, from projections of the ledger, with no filter by person. State
`building`.

**What breaks if an adapter goes, and where a wrong result went** (ADR-0147, UC-6.16, #333).
Built in the provenance store, the reporting component, the composition, the HTTP surface and
the web app: `GET /dependencies/remove/{adapter}` marks every step the adapter serves as
breaking or degrading by the removal test's rule on the configuration now;
`GET /dependencies/wrong-result/{run}/{step}` follows the result forward through
`ProvenanceStore.derived`, one recursive query, and marks every egress, with UC-4.11's counts;
`GET /dependencies/residency` holds each adapter against the rule. Pages `#/dependencies`,
linked from the register and from a result's origin. Still open: UC-4.11's error window, and a
laid-out graph instead of lists.
