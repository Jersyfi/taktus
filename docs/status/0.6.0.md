# Status of `0.6.0` — level 4

Part of `docs/status.md`: how far `0.6.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**A software factory as a worker** (#411, UC-8.15 `built`, ADR-0157). The capability `change.implement` can be delegated to an external software factory through its task API: `workers/factory/`, generic over submit, state and change, with a profile per factory and none for a product. It passes the worker suite, faults included, against a stand-in factory, and the removal test says *changed* with a second factory as the alternative. A worker declares where it stores (`data_location`), one that declares nothing counts as `elsewhere`, and a worker step goes only to a worker the tenant's residency rule admits, or fails naming the rule before anything is sent (UC-11.1 `building`). No real factory is reached yet.

**An outward message** (#435, UC-7.6 `building`). A connector step that delivers what a model drafted is held to a frame by rule (ADR-0142): the tenant's label added to its text, the step's own named checks, an independent check in a step of its own that answers `send` or `reject`, the tenant's delay and quiet hours, no send once a person answered in the case, and the frame's anchors on a promise and on mass sending at every level. `message.sent` names the case, the checks and the label beside the egress entry. `taktusctl messages` and `taktusctl case answered`; the defaults are NTC-0234, migration `0074`. No connector's intake records an answer in a case yet.

**Level 4** (#645, UC-7.1 `building`, UC-4.6 `building`). A process at level 4 runs as one at level 3 before a step starts, and heals a failure an adapter classified as repeatable on its own (ADR-0160): the step is admitted again at once against the budget, at most twice per step and run, never for an operation that cannot recognise a repeat and never for an action set lower, recorded as `step.healed`. Past that the run escalates and says why it was not healed. Every anchor halts a level-4 run with a decision request, and a raise to level 4 needs the approval and the history. Levels per risk class are not built.

**Package B builds `0.6.0` whole** (DEC-0222), on the branch `concept/package-b`. Four items of the roadmap carried no issue and now do: level 4 (#645), the skill lifecycle (#646), role-based agents (#647) and rules from precedent (#648).

**Rules from precedent** (#648, UC-7.10 `built`). Where the five most recent decisions of one anchor at one step of one process chose the same option without modifications, the decision component proposes a rule as a decision request naming them (ADR-0161); a person adopts or declines it, and an adopted rule answers each later request of its kind as it is raised, naming itself in the register. Only a tenant's own strategic anchor is ever answered by a rule (NTC-0249); migration `0089`. No command line or page lists or retires rules yet.

**The Warp outlook** (2026-10-13). Software factories such as Warp are far ahead where Taktus
had placed its proof, so Taktus proves itself on a real operation instead (DEC-0195,
`docs/research/2026-10-13-warp-review.md`): the second tenant is a business or, from 2026-11-01,
the owner's household (NEED-0027, #400); `0.6.0` adds a level-3 process of that tenant (#401);
the second domain of `0.7.0` is incoming invoice to payment release (#402), and IT operations
moved after `1.0.0` (#95). Ten features follow from the comparison (#403 to #411).

**The worker contract's three extensions** (#403, ADR-0139). The contract carries an
outbound-only binding, steering and handover, and a tool call may say whether it acts outward and
a model's answer is reported, which is the contract's part of #433. The conformance suite holds
them as W-19 to W-21, each proven by a fault of the reference worker. The reference worker
implements all three, and passes the whole suite connected outbound, behind no inbound port. A
take-over asks a worker that declares handover for its document. The control plane does not yet
send a message (#624) or host the binding (#625).
