# Status of `1.0.0` — contracts, licence, opening

Part of `docs/status.md`: how far `1.0.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**Images scanned, signed and pinned** (#347, ADR-0173). `.github/workflows/images.yml` publishes
every image on a version tag under the version and on a push to `main` under the full commit
hash, for the development instance (ADR-0020). Each image is pushed by its digest alone,
scanned from the registry with the pinned grype once per platform, and only then tagged and
signed keyless with cosign through the workflow's own identity: no key, no secret. A fixed
vulnerability of severity `high` or above fails the scan, and the image gets no tag. The job
`proof` scans `alpine:3.10.0`, known-vulnerable and pinned by digest, and builds nothing unless
that scan fails on findings. The job `record` writes every digest, with the chart's values that
pin them. The chart takes a digest for every image and `images.requireDigest` refuses one
without, held by `helm template` in `tests/governance/test_chart.py`. **Runs only on `main`**:
the workflow has not run yet; the scanner, the proof and the digest-first push were run by hand
against a local registry. Built fresh on 2026-10-31, the control plane, the three workers and a
connector passed; the backup image did not: its `rclone`, from the distribution, carries fixed
critical vulnerabilities in Go modules, so a first build refuses its tag until that moves. Not
a release process (M3.6).
