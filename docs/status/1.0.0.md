# Status of `1.0.0` — contracts, licence, opening

Part of `docs/status.md`: how far `1.0.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**A breaking change of a published contract fails** (#396, ADR-0171, NTC-0255). `make
gate-compat`, in CI's lane `contracts`, compares every schema and contract OpenAPI document with
the last release tag and classifies each difference, compatible or breaking, from the consumer's
side. A breaking change fails unless it is made as a new major version under a new `$id`.
`tests/tools/test_contract_compat.py` shows both outcomes against a repository with a release
tag. The repository has no release tag yet, only candidates of `v0.2.0`, so nothing is published:
the lane reports a change against the pull request's base and passes. It begins to fail
breaking changes after the first release. ADR-0019 rule 2 is amended: a released schema changes
only compatibly until the freeze. `make gate-contracts` holds the freeze record
`contracts/FREEZE.json` to its digests once the owner writes it (M3.5). It does not exist: the
contracts are not frozen.

**A foreign agent as a worker** (#349, UC-14.5 `verified`, ADR-0172). The worker contract has a
binding to the open agent-to-agent protocol (A2A 0.3, JSON-RPC), not a second contract:
`workers/a2a/` speaks the contract to the control plane and the protocol to one agent, which
needs to know nothing of Taktus. Its operator names the capability, the location and the
estimate; a step per status change of the agent's task, its seconds as `compute_seconds`, a
steering message sent into the task — which answers an agent that asks for input. It passes the
suite, faults included, against a reference agent; withdrawn, the removal test says *changed*.
No image and no real agent yet: that needs an agent a tenant chose, its address and its
credential `A2A_AGENT_TOKEN`.

**Images scanned, signed and pinned** (#347, ADR-0173). `.github/workflows/images.yml` publishes
every image on a version tag under the version and on a push to `main` under the full commit
hash, for the development instance (ADR-0020). Each image is pushed by its digest alone,
scanned from the registry with the pinned grype once per platform, and only then tagged and
signed keyless with cosign through the workflow's own identity: no key, no secret. A fixed
vulnerability of severity `high` or above fails the scan, and the image gets no tag. The job
`proof` scans `alpine:3.10.0`, known-vulnerable and pinned by digest, and builds nothing unless
that scan fails on findings. The job `record` writes every digest, with the chart's values that
pin them. The chart takes a digest for every image and `images.requireDigest` refuses one
without, held by `helm template` in `tests/governance/test_chart.py`. **Runs only on `main`**:
the workflow has not run yet; the scanner, the proof and the digest-first push were run by hand
against a local registry. Built fresh on 2026-10-31, the control plane, the three workers and a
connector passed; the backup image did not: its `rclone`, from the distribution, carries fixed
critical vulnerabilities in Go modules, so a first build refuses its tag until that moves. Not
a release process (M3.6).
