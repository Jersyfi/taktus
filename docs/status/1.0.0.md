# Status of `1.0.0` — contracts, licence, opening

Part of `docs/status.md`: how far `1.0.0` has got, checked against the code and the tests.
What the milestone must reach is in `docs/roadmap.md`. Kept current by every pull request that
changes its state.

**A breaking change of a published contract fails** (#396, ADR-0171, NTC-0255). `make
gate-compat`, in CI's lane `contracts`, compares every schema and contract OpenAPI document with
the last release tag and classifies each difference, compatible or breaking, from the consumer's
side. A breaking change fails unless it is made as a new major version under a new `$id`.
`tests/tools/test_contract_compat.py` shows both outcomes against a repository with a release
tag. The repository has no release tag yet, only candidates of `v0.2.0`, so nothing is published:
the lane reports a change against the pull request's base and passes. It begins to fail
breaking changes after the first release. ADR-0019 rule 2 is amended: a released schema changes
only compatibly until the freeze. `make gate-contracts` holds the freeze record
`contracts/FREEZE.json` to its digests once the owner writes it (M3.5). It does not exist: the
contracts are not frozen.
