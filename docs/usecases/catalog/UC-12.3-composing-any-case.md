# UC-12.3 — Composing any case

## 1. What must be achieved

The pattern of an assistant — a channel, an agent, knowledge, tools, a process and its governance —
is composed for any case, by a person or by Taktus: an onboarding assistant for new staff, answers
to sales questions, facility reports, a family organiser, a club's administration. A new case is
worked out in dialogue, without programming, and whatever is built this way is part of reporting,
controlling and governance from the start. Nothing runs past Taktus.

## 2. How it is verified

- A new case is worked out in dialogue (UC-1.2) and registered without code. A test takes one of the
  examples above from a description to a registered process version without a line of code written.
- Every composed application is a process version. A test runs one and finds every run in the
  ledger, in the value balance and under the process's autonomy statement.
- A composed application is assembled from entries of the catalogue, named by capability (ADR-0003).

## 3. Where the boundary lies

**Not every case done well.** A composed case is held to the same evaluations as any process
(UC-8.4). **Not a block builder.** The case is composed in dialogue, not by dragging blocks
(`docs/vision/non-goals.md`). **Not whole departments**, which are blueprints (UC-15.1).

## 4. What it rests on

Planning in dialogue (UC-1.2); a process from a description (UC-4.1); agents (UC-8.7); rollout
channels (UC-12.1); the adapter obligation (ADR-0003). Definition `UC-12.3`. The roadmap names no
version; `0.7.0`, with UC-12.1, is the session's proposal.
