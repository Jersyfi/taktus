# UC-13.2 — Method scaffolds — what good work with AI needs

## 1. What must be achieved

For typical undertakings Taktus brings the tools a project needs before AI can run it on its own.
For development these are use cases, architecture decisions, a test strategy and a definition of
done. Taktus creates and maintains them together with the person, instead of assuming that the
person knows they are needed. Scaffolds exist for several kinds of work and can be extended, and a
beginner reaches with them a project as well structured as a professional's. A scaffold is a
curated skill, in the same format and under the same lifecycle as a skill Taktus learned.

## 2. How it is verified

- The catalogue holds scaffolds for at least development, process automation and analysis.
- An organisation adds a scaffold of its own without code.
- A scaffold is a skill (UC-14.2) marked as curated. It passes the same evaluations and the same
  approval as a learned skill.
- A scaffold declares the artifacts a project needs. Taktus checks a project against its scaffold and
  names every artifact that is missing or no longer maintained.
- A scaffold creates its artifacts in the organisation's own systems where it has them — its
  repository, its knowledge system — not in a store of Taktus's own.

## 3. Where the boundary lies

**Not good content.** A scaffold makes sure the structure is there; whether a decision in it is
right stays with the person. **Not whole departments.** A scaffold at the level of a domain is a
blueprint (UC-15.1).

## 4. What it rests on

The skill lifecycle (UC-14.2) and the skill hub (UC-14.3), whose format needs an architecture
decision before either is built; principle 1. Definition `UC-13.2`, and chapter 9 of the definition,
whose "Taktus builds Taktus" used this repository's own scaffold — use cases, ADRs, a definition of
done — as the first example. Filed under `catalog` by ADR-0029, which calls a scaffold a blueprint as
its reason for the filing; ADR-0029 also states that the filing decides nothing about what a use case
requires, and the definition's reading — a scaffold is a curated skill, a domain-level one a
blueprint — is kept. The version is `0.6.0`, with the skill lifecycle.

## 5. What is proven so far

A scaffold is a skill directory in the open `SKILL.md` format with a `scaffold.yaml` beside it
that declares the artifacts, and templates to create them from (ADR-0307). The catalogue ships
three, for development, process automation and analysis (`scaffolds/`). A directory written by
an organisation registers the same way, with no code. A skill carrying `scaffold.yaml` is
registered with the origin `curated` and passes the lifecycle of every skill: no approval
without a passed round, a person's approval below level 4, production. A check names each
artifact present, missing, unmaintained or unread. It reads the repository at one commit with
the new operation `repository.files.dates`, and pages through `knowledge.pages.list`, whose
entries now carry `changed_at`. Unmaintained is measured against the project's newest change,
never the calendar (NTC-0279). Furnishing creates exactly the missing artifacts. Files arrive
as one branch and one pull request a person merges, and pages are written into the knowledge
system. A repeat creates nothing twice. Only a version in production furnishes; a check reads
a draft and names its stage. Proven against the fake repository service and the directory
connector (DEC-0225).

A process reaches both through the loopback connector's `orchestrator.scaffolds`, and a
person through `taktusctl scaffold check|furnish`, whose check exits 1 where an artifact is
missing or stale (ADR-0308). SC-01 of `blueprints/method-scaffolds/` names the development
scaffold in a step and carries evaluation cases: the shipped scaffold's round runs on them as
rehearsals, a person approves, and it reaches production and furnishes a project, shown end to
end against the fake repository service.

Not built: a page of the web app for a check. The process-automation and analysis scaffolds
have no shipped process that uses them, so they reach production only through a process of the
organisation's own. Nothing checks a project on a schedule unless a process does. Whether a
present artifact's content is right is never read (§3).
