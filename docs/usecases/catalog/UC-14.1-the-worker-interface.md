# UC-14.1 — The worker interface — execution units as interchangeable adapters

## 1. What must be achieved

Everything that executes — coding agents, agent runtimes, script runners, training jobs — is
attached through one interface, beside the connector contract for tools and channels and the model
contract for models. A **worker** executes; it does not decide. The interface asks a minimum of
every worker: take an assignment with its task, context, frame and autonomy level; stream its
events — progress, decisions, tool calls; report tokens and cost per step; estimate its demand
before it starts and signal its step boundaries; hand over its results as artifacts; receive its
credentials injected and never keep them; receive only the tools the process allows. A new worker is
attached in hours, not weeks. Every worker passes a conformance suite and gets its maturity from it,
processes name workers by capability, replacing one passes the removal test, and a reference worker
for the reference domain is part of the project.

## 2. How it is verified

- Every execution unit is reached through the worker contract (`contracts/worker/v1`, ADR-0007):
  HTTP for control, an event stream for what happens, JSON Schema as the definition. A worker is
  buildable without the core's language; a shell script with no AI at all passes the suite.
- Each part of the minimum is a check of the conformance suite: estimating before the start (W-02)
  and refusing beyond its limits before the start (W-10); a gapless, resumable event stream (W-03);
  consumption reported per step (W-04); a step boundary signalled (W-05) and a stop landing on it
  (W-06); a halt at the limits it was given (W-14); artifacts handed over and not duplicated on resume
  (W-11); no credential in an event, an artifact or a log (W-08); a tool outside the allowed tools
  refused (W-07); a host outside the allowed hosts refused (W-13).
- The suite fails on exactly the check a fault breaks; a test injects every fault it knows into a
  reference worker.
- A worker's maturity is derived, not claimed: *verified* is the suite passed and the removal test
  passed, and the record names the half that is missing. A production process at autonomy level 3
  or above uses only workers at *verified* or above (`docs/architecture/contracts.md` §3).
- Processes name workers by capability, never by product (ADR-0003).
- Replacing a worker passes the removal test (UC-8.9): the weekly process S-01 withholds it and
  records the verdict (W-12).
- Two proof cases pass the suite: a shell script with no AI, and a training run that holds a GPU for
  hours and returns a model artifact (ADR-0007). A reference worker for the reference domain, a
  coding worker, passes it too.
- A second real worker of each shape exists before a feature builds on worker behaviour
  (`docs/architecture/contracts.md` §4).
- A person who has not seen the repository wraps an existing command-line tool as a worker from
  `contracts/worker/v1/CONFORMANCE.md` alone and passes the suite within one working day. The trial
  is recorded, with every place the person stopped.

## 3. Where the boundary lies

**Not a good worker.** The contract promises the transport and the schema; a wrapper that cannot
estimate its demand or signal its boundaries gets a rejected assignment, not a pass (ADR-0007).
**Not a coding agent of Taktus's own**, which is a non-goal (`docs/vision/non-goals.md`). **Not the
isolation of a unit**, which is the execution port's and its adapters' (`docs/architecture/contracts.md`
§2.4). **Not native pause.** A worker that can pause refines the granularity; it is never required
(ADR-0005).

## 4. What it rests on

The worker contract over HTTP and events (ADR-0007), `contracts/worker/v1` with its checks W-01 to
W-14 and `CONFORMANCE.md`; the conformance suite under `src/taktus/conformance/` and
`taktusctl conformance run`; the workers `workers/script/` and `workers/claudecode/`; the maturity
record of the `catalog` component; the removal test as a process (ADR-0003, `blueprints/self-operation/`);
the limits as reservation and the halt at a boundary (ADR-0005, third amendment). Definition
`UC-14.1`, new in version 2. The version is `0.5.0`, where the conformance half of *verified* is
recorded so that a worker can reach it; the training worker and the second coding worker are
`0.4.0`.

## 5. What is proven so far

The script worker passes the suite in both profiles; the coding worker passes it
in both authentication modes, against a stand-in for its agent; every fault fails exactly its check;
an assignment that does not name the credential it needs is rejected before it starts; the report
claims no verification; *verified* needs both halves, and the record names the missing one — by the
named tests. The instance records the conformance half itself since #93: it runs the
suite against the worker its configuration resolves, records a pass and every fault as not passed,
and a pass counts only for the configuration it names. The training proof case, a second coding
worker and the one-day trial do not exist, and no worker on Taktus's own instance has both halves
yet, so no worker is *verified* there.
