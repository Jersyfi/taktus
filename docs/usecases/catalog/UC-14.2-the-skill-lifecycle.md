# UC-14.2 — The skill lifecycle — experience becomes know-how, under governance

## 1. What must be achieved

A **skill** is a reusable, versioned piece of know-how that a model or a worker uses for one kind of
task. Taktus and its workers notice recurring ways of working in what they do and write them down
as skills. Unregulated, that would collide with repeatability, so it runs as a lifecycle under the
same rules as a change of model or prompt: **observation** — patterns in runs, repeated corrections,
recurring requests, and what the automation coach sees; a **draft skill** in an open format;
**evaluation and a dry run**; **approval** according to the autonomy level — a person at levels 1 to
3, automatic at level 4 after n passed evaluations; **in production**, versioned; **the takeover
instructions updated**; **quality measured** in operation, with an automatic fallback to the
previous version when it gets worse. No skill reaches production without passed evaluations, every
skill's origin can be traced, Taktus learns at the level of the process and never from a person's
behaviour, and a skill that grew out of a person's own use belongs to that person.

## 2. How it is verified

- Every stage is a ledger entry, and a skill passes them in order. A test tries to approve a draft
  that has no evaluation and finds it refused.
- No skill reaches production without passed evaluations (UC-8.4) and a dry run. The dry run is a
  rehearsal: it acts on nothing outside the system (ADR-0030).
- At autonomy levels 1 to 3 a person approves. At level 4 approval is automatic after n passed
  evaluations. n has a floor that no configuration can go below; its value is set when this use case
  is designed for `0.6.0`, from the evaluation data of `0.5.0`, and it is higher for a skill used by
  an `exact` step (DEC-0028).
- A skill never changes what may produce a step's result: a skill used by an `exact` step guides the
  method, and the step's exactness class still bounds the result (ADR-0014).
- Every skill version names its origin: the observations, the runs and the corrections it was drawn
  from.
- A skill shared beyond one person names no person, and its origin names runs and processes, not
  people. A draft drawn from one person's own use belongs to that person, is private by default, and
  is shared only by that person's act.
- Before a new version is used for real, the takeover instructions of every process using the skill
  name that version (UC-6.3).
- Each version's quality is measured against its evaluations and in operation. A version worse than
  its predecessor beyond the declared tolerance falls back to the predecessor automatically; the
  fallback is decided by a rule over the measurements, never by a language model, and is recorded
  and reported.

## 3. Where the boundary lies

**Not sharing.** Offering approved skills to others is the skill hub, UC-14.3. **Not learning about
people.** Nothing in a skill describes how a named person works (principle 14). **Not a model.** A
skill is know-how a method uses; training a model for a step is method selection (ADR-0004).

## 4. What it rests on

Evaluations (UC-8.4); rehearsals (ADR-0030); exactness (ADR-0014); the takeover instructions, which
name the skills a process uses by version (UC-6.3); bundles, of which skills are a part (ADR-0011);
where drafts come from — proposals (UC-4.4), self-healing (UC-4.6), the automation coach (UC-13.3);
the floor for n (DEC-0028, answered). Definition `UC-14.2`, new in version 2. The version is `0.6.0`,
where the roadmap places the skill lifecycle.

**What is missing before this is built: an architecture decision on the skill format.** Chapter 5 of
the definition names an open format (`SKILL.md`) as the contract for skills and method scaffolds. No
ADR has chosen a format, and one must before this use case or UC-14.3 is built
(`docs/vision/history.md`).

**What an accepted decision supersedes in the definition's text.** The definition says n is
configurable, without a limit. DEC-0028 gives n a floor no configuration can go below, set from data
and higher for `exact` steps. Above the floor n stays configurable.
