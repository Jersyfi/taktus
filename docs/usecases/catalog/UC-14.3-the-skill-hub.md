# UC-14.3 — The skill hub — skills shared as the organisation's own

## 1. What must be achieved

Approved skills appear in the Taktus catalogue, as models and agents do: shareable with oneself, a
family, a team, a project team, a department or the whole company, each with an owner, a purpose, a
maturity and its evaluation history. Skills are in an open format and can be exported one by one
and as a bundle. Sharing follows the organisation's structure, use and contribution to quality can
be evaluated per skill, and a skill that grew out of a person's own use enters a circle only by that
person's active decision.

## 2. How it is verified

- Only skills approved through the lifecycle (UC-14.2) appear. Each entry names its owner, purpose,
  maturity and evaluation history.
- A skill exports on its own and in a bundle, in a format that can be read without Taktus.
- A skill shared with a circle — a unit of the structure (UC-1.4) — is visible and usable inside it
  and nowhere else.
- A skill drawn from a person's own use enters a circle only by that person's act. No one else can
  share it, an administrator included.
- Use of a skill and its contribution to quality are evaluated per skill. A person's own use is
  visible to that person; anyone else sees it aggregated by role, team or department.

## 3. Where the boundary lies

**Not a marketplace.** Skills from other organisations are after `1.0.0`. **Not approval**, which is
the lifecycle's (UC-14.2).

## 4. What it rests on

The skill lifecycle (UC-14.2) and its format, which needs an architecture decision before this is
built; the structure (UC-1.4); export as one package per process (UC-8.9); budgets and their reading
for a person (UC-8.5); the value of a process (definition `UC-9.3`). Definition `UC-14.3`, new in
version 2. The version is `0.6.0`, the catalogue.
