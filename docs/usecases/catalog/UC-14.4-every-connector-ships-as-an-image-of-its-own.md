# UC-14.4 — Every connector ships as an image of its own

## 1. What must be achieved

Every connector Taktus ships is built and shipped as an image of its own, and none of them is
in the control plane's image, as DEC-0011 holds for workers. Adding a connector, or changing
one, never changes the core image. The catalogue of `0.6.0` lists the connectors by capability
and maturity, and names the image each one ships as. An installation that ran a connector before
keeps running it after the upgrade, without a change to its configuration.

## 2. How it is verified

- The control plane image contains no connector code. `tests/architecture` checks it on the
  Dockerfile and the source; the image test checks it on the built image.
- No connector imports the control plane, and the control plane imports no connector.
- The chart starts each configured connector from its own image. So does the one-server install.
- The release builds and pushes one image per shipped connector, at the release's version.
- The conformance suite passes against every reference connector in its image.
- A configuration written for the release before, which named a connector by its module, renders
  that connector from its own image.
- The catalogue lists every shipped connector with its capabilities and its image.

## 3. Where the boundary lies

**Not a public catalogue of third-party adapters** (#348). **Not a release schedule per
connector**: every image carries the release's version. **Not the connectors that run inside
the control plane's process** because what they reach is the instance itself — the loopback and
the directory connector. **Not a maturity for a connector no instance configured**: a maturity
belongs to a configuration (ADR-0044).

## 4. What it rests on

DEC-0011, which keeps workers out of the control plane image; ADR-0009, which keeps the
reference adapters in this repository until `1.0.0`; ADR-0118, the release list; ADR-0158, the
layout, the images and the upgrade path. The connector contract `contracts/connector/v1` and
its suite. Issue #339, `0.6.0`.

## 5. What is proven so far

The control plane image is checked for connector code on its Dockerfile, its source and its
built image. Every connector's stage copies its own directory and nothing else. The chart and the
release workflow name every shipped connector's image, and an earlier release's module renders
the connector from its image. Every connector the release ships passes the suite from its image
against the fake of its product. The release list and `taktusctl conformance list` name each
connector's image.
