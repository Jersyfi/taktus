# UC-10.4 — A first rehearsed process in ten minutes, measured

## 1. What must be achieved

A person who has never used Taktus, and who is not technical, gets from installing Taktus to a
first process that ran as a rehearsal in ten minutes. One command installs Taktus. A **gallery**
then offers blueprints for typical small organisations: a family, a club and a small business. The
person chooses one. The plan dialogue turns it into their first process. A **rehearsal** — a run
that acts on nothing outside Taktus — shows what the process does before it does anything for
real.

The ten minutes are a measured time, not an estimate. A clock records them, and the measurement
is reported.

## 2. How it is verified

- **One command installs.** On a machine that meets the installation guide's requirements, one
  command, typed as the guide states it, brings up an instance that answers that it is ready. On a
  cluster, one command installs the chart's small profile. After that command, every step up to
  the rehearsal is done in the web app; the person types no further command.
- **A gallery of open files.** The web app offers a gallery with at least one blueprint for a
  family, one for a club and one for a small business. Each is bundles in open files of the
  repository, which `taktusctl bundle check` accepts.
- **Removable.** Removing a gallery blueprint's files removes it from the gallery. It breaks no
  other process and no test except its own. A test removes one and shows both.
- **Never compulsory.** A person creates a process without the gallery as before. No step of
  Taktus requires a gallery blueprint to exist or to have been chosen.
- **From the gallery into the plan dialogue.** Choosing a blueprint opens the plan dialogue with
  its first process as a proposal, which the person can change before rehearsing it. The process
  begins at autonomy level 1 or 2, with its reason (ADR-0026).
- **Rehearsed before it goes live.** The first process is rehearsed as UC-1.10 defines. On a newly
  installed instance with no connector configured, the rehearsal of each gallery blueprint's first
  process runs to its end. The process goes live only by commissioning after that rehearsal.
- **The time is recorded, never estimated.** A script records the time from the moment the install
  command is started to the moment the first rehearsal has finished, from the clock, and prints it.
  A test goes the same path without a person, on a newly installed instance, and records its time
  the same way.
- **Measured with a person new to Taktus.** At least one person who has not used Taktus and is not
  technical goes the path with the script running, with no help other than what the instance and
  the installation guide show. The repository reports the time it took, the machine and the
  network it ran on, and every place the person stopped. The requirement holds when the reported
  time is at most ten minutes. A longer time is reported as it was, with where the time went.

## 3. Where the boundary lies

**Not a visual builder.** The gallery offers blueprints and the plan dialogue changes them; drawing
a process is a non-goal. **Not every situation.** The gallery covers three typical ones and grows;
templates for the rest are UC-10.3. **Not the trial of UC-10.3.** That trial, with three people and
the whole guided start, belongs to `0.6.0`; this use case measures one path, in time. **Not a
connected system.** A gallery blueprint's first process reaches nothing outside Taktus; connecting
the person's own systems afterwards is UC-1.3. **Not a measure of a person.** The time belongs to
the path. The report names no person, and no figure assesses the one who took part (principle 14).
