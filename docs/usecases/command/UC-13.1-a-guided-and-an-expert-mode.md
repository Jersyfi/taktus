# UC-13.1 — A guided and an expert mode

## 1. What must be achieved

Two ways of working with Taktus. The expert mode is open and gives full control over prompts,
models and processes. The guided mode leads a person who lacks the background step by step: it
asks the right questions, proposes proven approaches and translates the terms of the trade. Both
reach the same results, a person can switch at any time, and the guided mode hides nothing — it
explains instead of leaving out.

## 2. How it is verified

- The same intent pursued in either mode produces the same command and, for a process, the same
  process version. A test pursues one intent both ways and compares the two.
- Switching mode at any point keeps the work in progress; nothing is lost and nothing is asked twice.
- Every setting that takes effect is reachable from the guided mode. A setting the guided mode does
  not ask about is shown with the value it takes and why.
- The mode is a preference of the person, not a permission. The same identity has the same rights in
  both (UC-7.3).

## 3. Where the boundary lies

**Not two products.** One system, two ways in. **Not teaching.** Recognising recurring work is the
automation coach, UC-13.3. **Not the views.** What a role sees is UC-6.4.

## 4. What it rests on

The dialogue in which a person says what they want, which is the `command` component's (ADR-0029);
the plan (UC-1.2); rights per role (UC-7.3). Definition `UC-13.1`. The roadmap names no version;
`0.6.0` is the session's proposal, with the rest of enablement.
