# UC-10.1 — Runs anywhere, at any scale, on any hardware

## 1. What must be achieved

Taktus works for everyone — a private person as well as a business — and runs anywhere, without being
bound to hosting by its maker: on a home server, in a small company, as a large deployment with high
availability, scaling and several tenants, in any provider's cloud, and in a regulated or state
environment that is cut off from outside networks and hardened.

The execution layer abstracts the hardware there is: ordinary processors, graphics cards, and dedicated
accelerators for artificial intelligence, including classes of processor that do not exist yet. Taktus
recognises the resources available, uses them well for local models, and makes visible which hardware
makes which capability possible.

## 2. How it is verified

- A private person installs Taktus with one command, and an organisation deploys it from a referenced
  description of its infrastructure, kept as code. Both are exercised by an automated test.
- The features are the same in every variant: one release, with configuration as the only difference.
  A test runs the same process, unchanged, in two variants and finds the same steps executed.
- Moving between environments — local and cloud, a graphics card and an accelerator — needs no change to
  a process or an agent, only to configuration.
- Taktus runs with every route to outside networks closed, its models local (UC-8.3).
- The resources an instance has — processors, memory, accelerators — are detected and shown, and for each
  local model it is shown which hardware it needs and whether the instance has it (UC-8.10).
- Taktus needs no service of its maker to run: no licence server, no account, no telemetry sent home.
- No instance runs on infrastructure it administers itself (ADR-0025).

## 3. Where the boundary lies

**Not every platform tested.** Which environments are exercised in continuous integration is the
roadmap's; this use case requires that none is excluded by design. **Not the cluster's operation.** The
infrastructure is run by its operator; Taktus watches what it needs from it (ADR-0031) and does not
administer what it runs on. **Not making a model fit hardware that cannot carry it.** Taktus says what is
missing; it does not promise that every model runs everywhere.

## 4. What it rests on

The business-critical requirements, among them several instances and restart without data loss
(ADR-0013); tenants and instances (ADR-0020); where an instance may run (ADR-0025); Taktus watching the
platform it runs on (ADR-0031); running on own hardware (UC-8.3) and limits that do no harm (UC-8.10);
`deploy/` with its compose file and chart. Definition `UC-10.1`. Filed in `governance`, which holds the
platform's capacity report (NTC-0064). The roadmap names no version; `1.0.0`, where a stranger must be able
to run Taktus without asking, is the session's proposal.
