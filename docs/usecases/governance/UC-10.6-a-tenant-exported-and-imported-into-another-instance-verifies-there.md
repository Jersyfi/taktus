# UC-10.6 — A tenant exported and imported into another instance verifies there

## 1. What must be achieved

A business can take everything Taktus holds of it to another instance: its processes, its runs,
its ledger, its provenance records and its artifacts. The other instance may be fresh. What
arrives there is shown to be what left, by the same checks an auditor would apply: the ledger
chain verifies from its first entry, and every run's provenance chain verifies. A run that was
waiting when it left continues where it waited.

## 2. How it is verified

- An automated test exports a tenant from one instance, with a finished run and a run waiting for
  a person, and imports it into a second instance with a database of its own, migrated and
  empty. On the second instance the ledger verifies from its first entry, it holds as many entries
  as the export names, the newest entry of every chain is the one the export names, and every
  run's provenance chain verifies against its ledger entries.
- In the same test every ledger entry, every run and every provenance record on the second
  instance equals the one on the first, and every object a run names by digest is held there.
- The waiting run continues on the second instance to its end, and the ledger still verifies.
- An import never writes into a tenant that holds anything already: it is refused, and nothing is
  written. An export whose bytes changed after it was written is refused.
- The export and the import are each recorded on the tenant's ledger, after the act, with the
  export's digest. The import's record says whether its check passed.

## 3. Where the boundary lies

**Not a backup.** A backup restores a whole instance to a moment, without Taktus (UC-10.5). An
export moves one tenant between two running instances, through Taktus.

**Not across releases without their migrations.** An export is imported into an instance whose
schema still has every store the export carries.

**Not development state.** An instance whose state is files under its state directory exports
nothing and says so.

**Not encrypted by Taktus.** The export holds the tenant's data in clear. Keeping it safe is the
operator's, as with a backup.

## 4. What it rests on

The roadmap's condition *Data export proven by re-import* (NTC-0265). ADR-0221 builds it, on the
chains of ADR-0164 and the object store of ADR-0165. Principle 13.

## 5. What is proven so far

Every condition of §2 is proven by the named tests against two PostgreSQL databases of the
tests' own, through `taktusctl tenant export` and `import`; the HTTP routes are held to the same
answers. Not done here: an export of a tenant whose objects do not fit in memory, which ADR-0221
bounds.
