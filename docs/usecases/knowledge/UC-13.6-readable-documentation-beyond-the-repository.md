# UC-13.6 — Readable documentation beyond the repository

## 1. What must be achieved

The people who administer Taktus and the people who use it can read how to do so where they read
everything else: an administration guide and an end-user guide, in the organisation's own knowledge
system, structured the way the organisation keeps its documentation — a wiki or otherwise.

The guides are generated from the repository and kept consistent with it. They are never a second
source of truth: what the repository says is what the guides say, and where the two differ, the
repository wins. It is the obligation UC-1.4 places on everything Taktus sets up — documentation in the
organisation's own knowledge system — applied to Taktus's own documentation.

## 2. How it is verified

- Both guides exist: one for administration — installing, configuring, operating, restoring — and one
  for the people who use Taktus. Each is placed in the knowledge system the organisation configured,
  in the structure it configured.
- Every page is generated from the repository, and names the files it was generated from and the
  commit it was generated at.
- A change merged into the repository that changes what a page says reaches that page at the next run
  of the process that generates the guides, and that process runs at least once a day. A page whose
  sources changed and that was not regenerated is shown as out of date.
- A page edited by hand in the knowledge system is not overwritten silently. The edit is reported to
  the person responsible for the documentation as a difference from the repository; the repository
  stays the source, and the edit reaches it only as a change to the repository.
- The guides follow the repository's rules for writing: one idea per sentence, no technical term
  before it is explained, no metaphor where a definition belongs. A guide for users explains without
  assuming that the reader is technical (UC-10.3).
- Generating the guides is a process of Taktus like any other, with its steps, methods and ledger
  entries. Switching it off leaves the repository's documentation complete (`docs/vision/non-goals.md`:
  nothing Taktus produces is compulsory).
- The guides carry no secret value and no internal address of an installation; what an operator must
  supply is named by its parameter, as `CREDENTIALS.md` does.

## 3. Where the boundary lies

**Not the repository's own documentation.** `docs/` stays where developers and sessions read it;
the guides are derived from it, not a replacement. **Not a documentation platform.** Taktus brings no
wiki of its own; where the organisation has no knowledge system, the guides are files it can open
without Taktus. **Not translation by default.** Which languages the guides are generated in is the
organisation's configuration. **Not the takeover instructions of a process**, which are UC-6.3 and are
part of the process version.

## 4. What it rests on

The organisation's structure and where things are recorded (UC-1.4); knowledge sources and connectors
to a knowledge system (UC-5.5); the writing rules of `CLAUDE.md` §10; the credential register's rule of
naming a parameter, never a value (`CREDENTIALS.md`). Epic E13, enablement, which is filed where its
data lives (ADR-0029): the source of these guides is the knowledge the repository holds. Stated by the
owner outside the definition, in conversation, as a requirement; for this tenant, the owner decided
that the wiki follows once Taktus manages itself (DEC-0057). The roadmap places it in `0.3.0` (#88).
