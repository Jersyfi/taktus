# Tests

One directory per gate (docs/architecture/project-structure.md §2). A directory with no tests yet
reports "no targets yet" and green: `tools/gate.py` turns pytest's "no tests collected" into
success and nothing else.

PostgreSQL comes from testcontainers, once per session, migrated to the current schema
(`conftest.py`). Without Docker the tests that need it skip and name the reason; with
`TAKTUS_REQUIRE_DATABASE` set — CI — they fail instead. `TAKTUS_TEST_DATABASE_URL` points them
at an existing, empty database. Tests keep apart through tenants and never clean up.

| Directory | Gate | Checks |
|---|---|---|
| `architecture/` | `make gate-arch` | adapter obligation, component boundaries, no product name in the core (ADR-0003, ADR-0016) |
| `conformance/` | `make gate-conformance` | both contracts. Worker: the stream rules against every transcript fixture; the suite (`src/taktus/conformance`) against the reference worker in both profiles, started as a separate process; the meta-test: every fault the reference worker can inject fails exactly its check. Connector: the rules against known-good and known-bad documents; the suite over MCP against the reference connector, started as a separate process against the fake service (also a process); the meta-test per fault; and what the fake holds afterwards — every write acted exactly once per key. `taktusctl conformance run` end to end for both |
| `governance/` | `make gate-governance` | anchors hold, limits never breach, least privilege; today: the correction anchor's trigger — a result has left the system exactly when an egress entry names it or anything derived from it (ADR-0022) |
| `exactness/` | `make gate-exactness` | an `exact` step never takes its final value from a variable method (ADR-0014, ADR-0018): on the shared kernel's `Step`, on the process domain's own rule, on every example bundle, and at run time — an exact step executes as a rule of the run component |
| everything else | `make test` | `composition/`: the daemon's settings — every `TAKTUS_*` variable validated with a message naming it, the effective configuration with every secret masked, and that no secret value reaches a log line rendered through the daemon's own processor chain · `contract/`: the Python bindings of the shared kernel and the worker contract match the schemas, their enumerations and patterns, and every example · `components/<name>/`: domain rules as tables, no mocks; application services against `fakes/` (a deterministic clock and identifiers, a scripted worker); `components/run/test_provenance.py`: a record for every completed step, the chain behind an artifact, no gap across a stop or a crash, growth within the bound of ADR-0021, what `verify` finds · `adapters/`: what is particular to one adapter; `adapters/connectors/`: the reference connector against `fakes/repository_service.py` in a thread — the restart test (a pull request opened for a step, then the same step on a connector with no memory of it: one pull request), permissions passing through, every error cause, intake from the recorded payloads with the signature verified before the body is read; `adapters/queue/`: **one suite, both implementations** of the queue and the leadership ports — exclusive claims under concurrency, a lease that expires, renewal, release, completion, the limit on attempts; one leader, the second waits, a dead leader replaced; `adapters/rest/`: the whole HTTP surface under the root and under a two-segment prefix — health, readiness, problem details, the read API, intake through a scripted connector and through the reference connector over MCP in-process, and `api/openapi.yaml` held to `make generate`; and `adapters/persistence/`: **one suite, both implementations** — every test runs against the memory adapter and against PostgreSQL with the same assertions, a disagreement is a finding about the port; plus what only the database can show (a raw statement sees only its tenant, the ledger and the provenance refuse to change, the chain behind an artifact is one statement, no drift between migrations and metadata, two instances append to one chain) · `components/run/test_runner.py`: the runner over the memory queue — claimed once, two runners never the same run, a shutdown releases at the boundary, a lost lease stops the run, a failing job is left for a person · `integration/`: the whole slice against the reference worker started as a separate process, `taktusctl run` end to end, **the restart test**: `taktusctl run` against PostgreSQL is killed mid-step and resumed by id, and its provenance chain has no gap at the boundary; **the scaling proofs**: two daemons in-process on one database — every run executed exactly once across two runners, two schedulers elect one leader and the survivor takes over; **the shutdown proof**: `taktusd` as a process receives a real SIGTERM mid-run, exits 0, the run is halted at a boundary with its job released, a second daemon under a non-root prefix resumes and finishes it; `taktusctl submit` queues a run. The four gate directories are excluded here and run under their own targets, so `make gates` runs every test exactly once |
